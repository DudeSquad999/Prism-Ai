# Contributing to Prism AI

Thank you for your interest in Prism AI. The project owner created the original ideas, product vision, goals, decisions, and direction for the project. Contributions should support that vision while improving clarity, accessibility, safety, implementation quality, or documentation.

## Before you contribute

- Read the [README](README.md), [product specification](docs/PRODUCT_SPEC.md), and [roadmap](ROADMAP.md).
- Search existing issues before opening a new one.
- For substantial changes, open an issue first to discuss scope and fit.
- Do not include secrets, API keys, tokens, passwords, private prompts, personal information, or proprietary content.

## Good contribution areas

- Documentation clarity and editing
- Accessibility improvements
- Static prototype refinements
- Test scenarios that clearly distinguish examples from verified facts
- Security and privacy improvements
- Small, well-scoped implementation tasks approved by the project owner

## Pull requests

1. Keep each pull request focused on one purpose.
2. Explain what changed and why.
3. Update relevant documentation.
4. Test the local static prototype in a browser when changing interface files.
5. Confirm that no secrets or personal data are included.
6. Respect the project's privacy, transparency, uncertainty, and user-control principles.

## Writing guidelines

- Use clear headings, short paragraphs, and concrete wording.
- Separate implemented behavior from plans and future ideas.
- Do not claim that a model, workflow, or feature is always best or perfectly accurate.
- Clearly label demonstrations and sample content.
- Do not use em dashes. Use commas, periods, parentheses, colons, or hyphens instead.

## Code guidelines

- Prefer small, readable changes.
- Keep the static prototype dependency-free unless a change is discussed first.
- Do not add network requests, analytics, tracking, AI provider integrations, or backend services without explicit project-owner approval.
- Use semantic HTML, accessible labels, keyboard support, and visible focus styles.

## Reporting problems

Use the bug report template for reproducible problems. For security concerns, follow [SECURITY.md](SECURITY.md) instead of publishing sensitive details in a public issue.

## Code of conduct

Be respectful, constructive, and specific. Focus criticism on the work, not on people.

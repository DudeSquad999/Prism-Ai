# Community guide

This guide explains where to ask questions, propose improvements, report defects, and contribute to Prism AI.

## Pick the right place

| If you want to… | Use |
|---|---|
| Ask how something works or get setup help | [GitHub Discussions](https://github.com/DudeSquad999/Prism-Ai/discussions), if enabled |
| Share a possible feature and discuss trade-offs | Start a discussion; create a feature issue when the request is clear |
| Report a reproducible defect | [Bug report form](https://github.com/DudeSquad999/Prism-Ai/issues/new?template=bug_report.yml) |
| Propose a focused improvement | [Feature request form](https://github.com/DudeSquad999/Prism-Ai/issues/new?template=feature_request.yml) |
| Submit code or documentation | Open a pull request using the repository template |
| Report a security vulnerability | Follow [SECURITY.md](../SECURITY.md); do not post exploit details publicly |

## Suggested discussion categories

If GitHub Discussions is enabled, use a small set of clear categories:

- **Announcements:** maintainer-only release and project updates.
- **Q&A:** setup questions and general help.
- **Ideas & feedback:** proposals, design feedback, and trade-offs.
- **Show and tell:** real examples, experiments, and workflows.
- **General:** topics that do not fit elsewhere.

Avoid creating a category for every feature.

## Before posting

- Search existing discussions, issues, and the README.
- Say whether you mean the static demo or a Windows application.
- Include the release version and environment when relevant.
- Share steps and observations, not only conclusions.
- Label guesses, mockups, and planned features as such.
- Be respectful and keep one topic per thread.
- Never post API keys, credentials, private conversations, or unredacted logs.

## How to give useful feedback

For feature ideas, describe the problem before prescribing a solution. Discuss trade-offs and how success could be checked.

For bug reports, use the issue form so the maintainer can reproduce and track the problem. For a discussion that becomes a defined task, summarize the decision and link the issue or pull request.

## Community standards

Follow the [Code of Conduct](../CODE_OF_CONDUCT.md). Constructive criticism is welcome; harassment, doxxing, and exposing private information are not.

## Maintainer workflow

- Keep discussions open for feedback, and convert well-defined defects into issues.
- Link duplicate posts to the canonical thread.
- Summarize decisions and link related issues or pull requests.
- Do not promise delivery dates or describe planned work as released functionality.
